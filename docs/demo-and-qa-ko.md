# Divercity Pay 시연 및 점검 기록

작성일: 2026-11-09. 이 사이트는 테스트 시제품입니다. 실제 카드 결제나 계좌 송금은 실행되지 않습니다.

## 3분 시연 순서

1. [홈페이지](https://rent-card-payment.vercel.app/)에서 서비스 설명과 단계별 미리보기를 보여줍니다. 홈페이지 미리보기의 입력값과 파일은 운영 신청으로 제출되지 않습니다.
2. 로그인 후 **My dashboard → Apply for rent payment**로 이동합니다. 이 별도 페이지가 실제 테스트 신청 접수 경로입니다.
3. 계약서, 주소·기간·월세, 임대인 계좌, 최종 확인의 네 단계를 보여줍니다. 시연 때는 실제 계약서나 계좌 대신 별도 준비한 가상 자료만 사용합니다.
4. 이미 접수한 테스트 신청번호 `DP-20261109-DE3D973E`를 신청 내역에서 찾습니다. 신청자 화면에서 제출 정보, 계약서, 상태 이력을 확인합니다.
5. 관리자 계정으로 로그인해 같은 번호를 검색합니다. 신청자와 계약서 정보를 대조하고 심사 기능을 설명합니다. 화면에서 승인·반려를 누르면 테스트 신청 상태가 실제로 바뀌므로 반복 시연에서는 상세 조회까지만 합니다.
6. 테스트 모드 안내를 다시 보여주며 시연을 마칩니다. 실제 금융사 연결, 결제 승인, 임대인 송금은 아직 없습니다.

## 확인된 항목

- 일반 사용자 테스트 신청 `DP-20261109-DE3D973E`가 접수됐고, 신청자와 관리자 화면에 같은 신청 정보가 표시됐습니다.
- 신청자와 관리자가 계약서 서명 URL로 파일을 열 수 있었습니다. 다른 일반 계정으로는 타인의 신청 상세와 관리자 화면 접근이 거부됐습니다.
- 운영 Supabase에서 `contract-documents` 버킷은 비공개이고 `storage.objects`의 RLS가 활성화돼 있습니다. 조회 정책은 소유자 경로 또는 관리자 역할에 한정됩니다. 일반 사용자 역할과 테스트 계정 ID를 적용한 읽기 전용 DB 조회에서는 본인 파일 `true`, 다른 계정 파일 `false`가 나왔습니다. 인증 정보나 서명 없이 원본 Storage URL을 열면 파일을 받지 못했습니다.
- 관리자 승인·반려와 신청 취소의 상태 이력 및 알림을 테스트했습니다. 반려 사유는 페이지 내부 입력창으로 처리됩니다.
- 관리자 파일 정리 화면에서 7일 이상 된 미연결 계약서 조회 결과는 0개였습니다. 접수된 신청의 파일은 정리 대상이 아니므로 삭제하지 않았습니다.
- 배포된 신청 화면을 390px 브라우저 폭에서 네 단계까지 확인했습니다. 진행 표시와 최종 검토 화면에 가로 넘침이 없었고, 빈 계약서·주소·날짜·계좌 입력은 진행을 막으며 첫 오류 입력칸으로 초점이 이동했습니다. 최종 확인 체크가 없으면 제출되지 않습니다. 이 점검에서는 테스트 자료를 선택만 하고 제출하지 않았습니다.

## 남은 보안·운영 검증

- 다른 일반 계정의 인증 세션으로 **계약서 원본 Storage API**를 직접 호출하는 거부 테스트는 아직 완료되지 않았습니다. DB 역할 시뮬레이션은 정책 동작 확인이며, 실제 사용자 토큰을 이용한 API 검증과 동일하지 않습니다.
- 서명 URL은 유효 시간 동안 링크를 가진 사람에게 열립니다. 시연 자료에 서명 URL을 넣지 않고, 화면 공유 시 주소창을 가립니다.
- 테스트 계정의 이메일은 수신할 수 없는 예시 주소입니다. 비밀번호 복구가 필요하면 새 테스트 계정을 만듭니다. 실사용자의 계약서, 계좌, 전화번호는 시연에 사용하지 않습니다.
- 서비스 출시 전에는 금융사·PG 계약, 자금 흐름, 개인정보 및 결제 보안 검토가 별도로 필요합니다. `launch-readiness-ko.md`를 참조합니다.
