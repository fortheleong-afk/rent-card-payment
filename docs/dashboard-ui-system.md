# Divercity Pay — 사용자 대시보드 디자인 기준

적용일: 2026-11-19. 적용 범위는 `/dashboard`, `/applications/new`, `/applications/[id]`이다.

## 적용 방식

- Astryx core / theme-neutral / CLI **0.7.16**, StyleX peer **0.19.0**.
- 공식 React 19 요구사항에 맞춰 react / react-dom **19.2.9**로 함께 업데이트했다.
- 실제 Astryx `Theme`, `LinkProvider`, `Button`, `Badge`를 사용한다. 링크 버튼은 Next.js Link로 렌더링되며, 페이지 이동과 클릭 행동을 구분한다.
- 기존 `getJourney`, `priorityApplication`, `tenantTask`, Supabase 조회, 임시 저장·제출 복구 안내를 재사용한다. DB 정책, SQL, 결제/송금 RPC는 변경하지 않는다.
- `components/ui/AccountTheme.tsx`가 사용자 작업 화면에 공통 테마를 제공하고, `DashboardTheme.tsx`는 호환 export로 유지한다. 다른 화면까지 일괄적으로 바꾸는 글로벌 reset은 추가하지 않는다. 기존 앱 reset 위에 Astryx의 컴포넌트 CSS를 사용한다.
- CLI 초기화 문서는 `docs/astryx-dashboard-reference.md`에만 저장한다. 전역 에이전트 설정과 기존 AGENTS.md를 변경하지 않는다.

## 공통 규격

| 항목 | 기준 |
|---|---|
| 본문·헤더 최대 너비 | 68rem, 같은 좌우 기준선 |
| 좌우 여백 | 데스크톱 2rem / 모바일 1rem |
| 기본 여백 단위 | Astryx 4px 단위 spacing tokens |
| 섹션 간격 | 32px / 모바일 24px |
| 카드 안쪽 간격 | 32px / 모바일 20px |
| 카드 헤더 간격 | 24px / 모바일 20px |
| 관련 텍스트 간격 | 8–12px |
| 버튼 최소 높이 | 44px, 큰 버튼 48px |
| 페이지 제목 | 28–36px, rem 기반 clamp |
| 섹션 제목 / 본문 | 20–24px / 15–16px |
| 보조 정보 | 13px, 충분한 대비 유지 |
| 카드 / 버튼 모서리 | 12px / 8px |

브랜드 색과 폰트는 `components/ui/divercity-theme.ts`에서 관리한다. 화면별 CSS에서 같은 색을 반복 정의하지 않는다. 현재 브랜드 파랑과 Manrope / Noto Sans KR을 유지한다.

## 읽기 순서와 상태

1. 화면 제목과 새로고침
2. 테스트 모드 안내 및 기존 알림·프로필 링크
3. 제출 복구가 필요한 임시 신청 또는 우선 확인할 신청
4. 현재 상태, 다음 할 일, 처리 단계, 하나의 주요 행동
5. 신청 목록·필터와 전체 내역
6. 도움말과 계정 링크

현재 상태와 다음 행동은 넓은 화면에서 두 열, 좁은 화면에서는 DOM 순서대로 한 열로 표시한다. 필터는 좁은 화면에서 두 열로 줄바꿈하여 숨겨진 가로 스크롤 없이 조작한다. 기존 필터의 span 규칙이 Astryx 내부 라벨·배지에 영향을 주지 않도록 범위를 분리하고, 모바일 새 신청 링크는 전체 너비로 표시한다. 새로고침 중에는 Astryx의 로딩 상태와 기존 중복 요청 가드를 함께 사용한다.

## 접근성과 Modern Web Guidance

- `responsive-design` 가이드: rem 제한과 viewport 값을 함께 쓰는 clamp 제목 크기, 좁은 화면 한 열 전환, `dvh` 높이로 모바일 브라우저 변화 대응.
- 기본 DOM 순서와 링크 의미 유지. 현재 페이지 aria-current, 필터 aria-pressed, 상태 변경 안내, 키보드 focus-visible 및 본문 건너뛰기 링크를 제공한다.
- 버튼 클릭 영역 44px 이상. 카운트는 Badge, 신청 상태는 기존 문구와 상태 표시를 유지한다.
- 화면 등장 때문에 콘텐츠를 숨기는 애니메이션을 추가하지 않는다.

## 재검증 명령

- `npm run theme:build`: 테마 원본에서 CSS/JS/타입을 재생성
- `npm run theme:check`: 생성 파일과 테마 원본 일치 여부 확인
- `npm run lint`
- `npm run test:core`
- `npm run build`
- `npm run astryx -- doctor --built .next`

테마 빌드 결과도 GitHub에 함께 저장하여 배포 시 별도 테마 생성 단계에 의존하지 않는다. 후속 화면은 이 테마를 재사용하되, 신청 처리와 관리자 기능을 중복 구현하지 않는다.

## 검증 범위

빌드, 타입 검사, 린트, 핵심 회귀 검사 및 Astryx doctor 결과를 확인한다. 브라우저에서는 기존 로그인 세션의 신청 표시, 필터의 빈 상태와 복귀, 새로고침, 신청 상세 이동, 모바일 줄바꿈을 확인한다. 결제·송금 테스트 모드는 유지하며 새 금융 거래는 실행하지 않는다.

## 신청 작성·상세 화면 확장

- `AccountScreen`으로 헤더·본문 너비, 제목, 상태 안내와 건너뛰기 링크를 통일한다.
- 신청 작성은 저장 안내 → 단계 → 입력 → 이전/다음 순서이며, 입력은 16px·48px 높이와 기본 브라우저 입력 의미를 유지한다. 필수 항목·오류 연결, 임시 저장, 새로고침 복구와 제출 처리는 기존 로직을 재사용한다.
- 단계별 필드셋과 제목을 연결한다. 제출·이전·취소 확인 버튼은 기존 native button을 유지해 disabled·submit·focus 동작을 보존한다. 일반 행동과 링크는 Astryx Button을 사용한다.
- 상세는 상태·다음 행동, 금액과 신청 정보, 계약서, 상태 이력, 취소 순으로 표시한다. 모바일은 동일 DOM 순서의 한 열로 전환한다.
- 공개 안내나 관리자 화면에 전역 CSS를 추가하지 않는다. 페이지별 CSS Module로 레거시 선택자와의 충돌을 제한한다. 실제 결제·송금과 Supabase 권한·정책은 변경하지 않는다.

## 관리자 화면 적용

- `/admin`과 `/admin/storage-cleanup`도 `AccountTheme`을 재사용한다. 관리자 안내는 한글로 유지한다.
- 업무 목록은 기존 사이드바와 표를 유지하고 최대 본문 68rem, 좌우 32px/모바일 16px, 패널 32px/모바일 20px를 적용한다. 필터·검색·정렬과 상세 패널의 여백을 같은 spacing token으로 통일한다.
- 기본 버튼·입력창은 48px, 검색·선택·반려 사유 입력은 16px 글자 크기다. native disabled와 기존 포커스 트랩·Escape 복귀를 유지하도록 심사·시뮬레이터 버튼의 동작은 변경하지 않는다.
- 좁은 화면에서는 기존 단계 선택과 신청 카드형 표를 유지한다. 상세 패널은 한 열로 표시하고 하단 행동과 닫기 버튼을 유지한다.
- 권한 검사, 검색·정렬, 계약서 서명 URL, 심사 RPC, 상태 이력과 시뮬레이터 코드는 변경하지 않는다. 보관 점검은 조회와 삭제를 계속 분리하고 기존 삭제 전 재조회·확인 절차를 유지한다. 실제 결제·송금은 테스트 모드다.

## Divercity House 브랜드 색상 통일 (2026-11-20)

기준: https://divercityhouse.com/ 실제 버튼·링크의 렌더링 색상. 주요 보라색 `#A230FF`, 연보라색 `#D2BCF7`를 공유하고, Pay의 업무 화면은 흰색 바탕과 짙은 중립색 본문을 유지한다.

- `app/brand-colors.css`는 기존 화면의 공통 색상 변수를 정의한다. 기존 `--blue`, `--navy` 이름은 호환성을 위해 유지한다.
- Astryx 화면은 `components/ui/divercity-theme.ts`와 생성 CSS/JS를 함께 갱신한다. 브랜드 강조색 `#A230FF`, 링크·포커스 `#7620B2`, 배경 `#FAF7FD`, 본문 `#242028`, 보조 본문 `#625A6D`, 구분선 `#E5DDEA`.
- 흰색/주요 보라색 대비 4.77:1, 흰색/링크 8.02:1. 초록·빨강·노랑의 성공/오류/주의 의미는 유지한다.
- 홈페이지·로그인·회원가입·사용자·관리자 화면의 기존 파란색 고정값을 역할별 공통 변수로 교체한다. 레이아웃·필드·데이터 처리·결제 및 송금 모드는 변경하지 않는다.

## 색상 후속 점검

공개 7개 경로와 사용자·관리자 경로를 실제 브라우저에서 확인했다. 모바일은 390px에서 홈페이지, 회원가입, 신청, 상세, 관리자 패널을 확인했다. 렌더링된 기본 텍스트의 대비와 가로 넘침을 측정했다.

Astryx에서 상속하던 info, blue 역할 및 선택·호버 inset 테두리의 기본 파란색을 보라색으로 재정의했다. 안내 문구는 짙은 보라색/연보라색 조합으로 지정하고, success/error/warning 토큰은 유지한다. 중립 테마의 로컬 상태 강조 토큰은 `localTokens`에서 재정의한다. 생성 CSS/JS는 테마 소스에서 다시 생성한다. 인증·업로드·심사·금융 로직은 수정하지 않는다.
